# 本科教务账号导入 · 当前实现与验证

2026-10-03。现有 0.21.0 体验版以文件导入为主；本轮增加账号登录导入。真实账号端到端测试尚待用户在本机验证页提交，不能仅凭模拟测试宣称导入成功。

## 实现

原生页面：约会 → 双人课表 → 账号密码自动导入 → 阅读说明 → 连接教务网 → 输入学号、密码、学年、学期（必要时验证码） → 自动读取 → 课表预览 → 核对保存。

学校公开流程核对来源：
- https://zdbk.zju.edu.cn/jwglxt/js/globalweb/comp/xtgl/loginV2022.js
- https://zjuam.zju.edu.cn/cas/js/login/login.js
- https://zjuam.zju.edu.cn/cas/js/login/security.js
- https://zdbk.zju.edu.cn/jwglxt/js/comp/jwglxt/xkgl/kbcx/xskbcx.js

SSO 服务地址来自公开的 `login_cxSsoLoginUrl.html` 响应。课表页面与查询脚本路径已通过 Safari 中用户已登录的页面源码核对。重新载入时 Safari 会话已过期，因此没有从浏览器提取 cookies 或复用登录凭据。

实际协议：GET CAS 登录页 → execution + 会话 cookie → getKaptchaStatus / getPubKey → 必要时获取图片验证码 → POST RSA 密文 → 跟随 HTTPS SSO 跳转 → GET 课表页 → POST cxXsKb。仅访问两个固定的学校域名，不接受客户端提供的 URL。额外认证无法自动处理时明确提示，不绕过验证码。

## 凭据处理

明文密码仅存在手机端临时内存，不进入 Page.data、日志或本机存储。密码输入框在提交/离开页面后销毁。前端自主实现与学校一致的 RSA 编码，不使用 BigInt，已和学校原始算法对照验证。

云端只接收学校 RSA 密文；不记录教务动作的异常对象，避免网络上下文泄露。数据库 profiles.schoolAuth 仅保存未认证的 CAS 准备状态、随机 ID 与五分钟失效时间，不含密码或已认证会话。每次提交在事务中先消费准备状态，其他微信身份无法取用。过期状态逻辑失效，后续连接/取消覆盖或清除；尚未配置物理 TTL 删除，不能宣称过期时已物理删除。

认证成功后的 cookies 只存在一次云调用内存中，不回传前端、不写入数据库。导入结果先预览，保存仍调用原 saveTimetable，与原来的共享同意流程一致。

每微信身份十分钟最多六次连接；学校错误登录风控仍以学校为准。错误或二次认证提示不会自动重试密码。

## 验证

- 公开学校登录准备流程真实网络验证成功：execution、RSA 公钥和准备 cookie 可取得，当次未要求验证码。
- RSA 与官方 security.js 输出对照一致（短密码及跨分块密码）。
- 新增协议输入验证、域名约束、单次会话消费、身份隔离、日期/单双周、前端密码清除、晚到响应丢弃测试。
- 原有和新增测试共 80 项通过。
- 尚待：用户实际账号登录、实际 JSON 返回解析、验证码出现时真机图片渲染、微信云端读取整个课表。

本机验证入口 `node scripts/verify-school-login.js`，仅监听 127.0.0.1:4174，检查 Host、Origin 和随机请求令牌；不保存账号、密码、课表到文件，不向小程序云端上传。`/status` 只返回成功数量或脱敏错误。完成验证后关闭该进程。

### 对照用户提供的 login-zju 后发现的认证缺陷

参考项目：用户指定目录内 ZJU-live-better-main/node_modules/login-zju 1.0.9 的源码映射（zjuam.ts、zdbk.ts、cookie-jar.ts），仅阅读代码，没有读取 .env、密码或已保存的登录凭据。

根因证据：实际 CAS 初始响应下发 `_csrf; Domain=zju.edu.cn; Path=/`，旧 HTTP 客户端错误地用出站域名白名单校验 Cookie Domain，丢弃这个父域 Cookie。已允许学校父域 Cookie，同时仍将网络目标严格限制为 zjuam.zju.edu.cn 和 zdbk.zju.edu.cn。新增回归测试覆盖父域 Cookie 发送、不同主机的 JSESSIONID 隔离及非学校域拒绝。

按照参考项目，认证前增加 POST login_cxSsoLoginUrl.html 建立教务 JSESSIONID/route。空 POST 请求也必须维持 POST 方法。修复后的公开网络准备流程取得教务及认证两组会话和学校父域 _csrf、_pv0。用户尚需再次提交真实账号，不能将此当作认证成功。

# 同行周纪念版交付与试测

## 可运行的产品路径

| 入口 | 后续体验 | 返回与异常 |
| --- | --- | --- |
| 湖畔情侣榜 | 本周积分、名次、追分差额、排名名单、周结算入口 | 单方同意/空榜明确提示，无虚构参赛者 |
| 点击组合 | 公开名片仅匿名名称、分数、名次；自己的名片有周历和分类得分 | 无权查看他人活动、地点、感想；退出榜单后不再可从名单打开 |
| 去赚积分 | 选类别 → 灵感计划 → 发起 → 另一半加入 → 计时 → 双方确认 | 未绑定、已有进行中活动不可重复发起；可取消 |
| 活动完成 | 积分结果弹层 → 查看榜单或写回忆 | 重复类别/当日封顶得 0 分，仍保存回忆并说明原因 |
| 周结算 | 上周结算 / 本周进度 / 最近 12 周 → 领取数字纪念章 | 当前周不可领取；空周不生成虚假奖励 |
| 纪念海报 | 湖畔夜绿 / 日光信笺 → 原生 PNG → 预览 / 保存 / 分享入口 | 生成失败可重试，相册拒绝后保留图片并提供权限入口 |
| 邀请 | 生成码、复制码、云模式原生分享邀请卡片，接收方打开后手动加入 | 12 位码、24 小时有效、单次使用；演示不跨设备 |

## 周结算约定

- 北京时间周一 00:00 切换，按双方最后确认的服务端完成时间记入周次。积分不在午夜通过客户端清零，而是分周存储。
- 活动完成与当前周积分写入同一数据库事务；周报保留独立计数、天数和分类得分，300 条近期回忆截断不影响此版本开始积累的周账本。
- 排名用本周公开参与组合积分降序，同分 1、1、3。仅查询前 50 组，不声称知道名单外的准确名次；边界同分可能只返回其中一部分。
- 本周退出公开榜立即影响本周名单；历史周参与状态不改变。历史周报仅本人情侣空间可取，不提供全校历史名单。
- 纪念章按周积分最高档：1 分初见微光、40 分默契生长、100 分闪光同行。无现金、实物或商家券。未参与公开排名也可获得积分纪念章。
- 领取只接受最近 12 个结束周的有效周一日期；身份从 OPENID 获取，忽略客户端传入的积分、身份、其他情侣空间。
- UI 可重访最近 12 周；服务端目前未自动删除更早账本。生产运行前确定数据保留、导出和删除政策。

## 云部署清单

1. 使用团队自己的小程序 AppID 和云开发环境，保持测试环境与正式环境分离。
2. 创建 profiles、couples、invites、weeklyScores、rewardClaims 五个集合；客户端安全规则统一 `{ "read": false, "write": false }`。
3. weeklyScores 复合索引：listed 升序、key 升序、points 降序。文档 ID 为 `roomId_YYYY-MM-DD`；rewardClaims 使用相同形式，每个周次一份领取记录。
4. `npm run sync` 后部署 cloudfunctions/api 并云端安装依赖。检查新 season.js 已上传。将 config.js 切换 cloud 并填写云环境 ID。
5. 从两台手机、三个测试微信号验证绑定、隔离、重复确认和重复领取；验证数据库事务与索引在真实环境正常工作。
6. 申请/配置小程序隐私说明中的图片保存用途，实际手机上验证相册允许、拒绝、撤销权限；海报不上传服务器，只有用户保存或主动分享才离开当前页面。
7. 分享小程序需真实体验成员测试；未上线前不画假二维码，当前没有小程序码生成服务。

## 原生人工验收（本机）

已验证：榜单进入自己的名片、名片进入周结算；上周无记录空状态；本周进度不提供领取；演示进入下一周后保留 8 分、1 次活动、1 天、排名第 1；领取成功；纪念海报实际生成并在微信图片预览中完整显示；拒绝相册授权后可恢复到页面并预览；湖畔夜绿与日光信笺样式切换均实际生成图片；再次打开已结算周报仍为已领取；双人听歌完成后出现 +4 积分结果弹层并可返回积分已更新的榜单。

25 项自动规则与云路由检查通过：双人绑定、身份隔离、时间要求、每日封顶、幂等确认、并列名次、跨周、历史周次边界、提前领取拒绝、双方重复领取、历史领取状态持续、账本不依赖近期回忆数量。

尚未验证：真实云数据库与网络并发、两台实体手机、真机相册保存成功、微信好友实际收到分享卡片。工具中的拒绝授权测试后，如需在同一模拟器测试成功路径，请在海报页点“检查相册权限”自行开启。

## 校园试测建议（产品验证，不是已实现认证）

第一轮邀请 5–10 对自愿参与情侣，用一周验证“绑定—活动—周报—保存”的流程。收集每一步完成率、放弃点、异常计分、重复点击与网络失败情况。下一轮再接定位：测试湖畔、图书馆、教学楼与操场的误差，记录同场误拒率，不能把某个固定距离直接当事实认证。

## v0.8 积分榜补充

本机演示新增 8 组虚构情侣，公开榜与周报使用同一排名数据。积分按演示日期所在周的天数增长，每组每日不超过 30 分。自己的组合仍须双方同意后上榜；退出不会清空其他组合。云端模式没有示例数据，仍需部署及多用户联调。

## v0.13 约会操作闭环
底部“赚积分”改为“约会”，有活动时显示“约会中”。发起成功后留在约会页；参与状态、剩余分钟、双方完成状态、编辑记录和取消均位于本页。固定底栏按状态显示加入、等待、确认完成。无绑定时底栏提供可点击的邀请入口。

首次加载存在未完成活动时自动进入约会；榜单、首页继续入口统一导航至约会页。活动选择区在进行中时由约会操作卡替代，结束后恢复，完成弹层提供“再约一次”。云端身份与计分规则未更改，仍按既有 15 秒轮询刷新状态。

30 项测试通过，新增页面级双人加入/完成/不重复计分流程、失败不跳转、重开恢复测试。原生开发者工具验证现有自习活动恢复和榜单继续入口，未修改该现有约会状态。

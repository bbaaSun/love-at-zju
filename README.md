打开 http://127.0.0.1:4173 。不需要安装依赖。仅本机可访问。

## 接入云端，进行两台手机联调

需要你们自己的小程序 AppID 和已开通的云开发环境；本项目没有创建账号、开通付费服务或代为发布。

1. 在 `project.config.json` 填写 AppID。
2. 创建数据库集合：`profiles`、`couples`、`invites`、`weeklyScores`、`rewardClaims`。
3. **这五个集合都禁止客户端直接读写。** 在安全规则中设置如下内容；数据仅由云函数访问。不要为图方便设置成所有人可读写。

```json
{ "read": false, "write": false }
```

4. 为 `weeklyScores` 建立复合索引：`listed` 升序、`key` 升序、`points` 降序。它用于本周榜单与历史周报的排名查询。
5. 修改 `miniprogram/config.js`：

```js
module.exports = { mode: 'cloud', cloudEnv: '你们的云环境 ID' };
```

6. 执行 `npm run sync`，同步共享计分规则到云函数目录。
7. 在微信开发者工具中选择对应云环境，右键 `cloudfunctions/api`，上传并部署，选择云端安装依赖。云函数使用 `wx-server-sdk`；Node 运行时建议选受平台支持的现代版本。
8. 两个体验成员分别打开首页。A 生成 12 位邀请码，B 输入邀请码加入。邀请码有效期 24 小时，成功绑定后失效。
9. 按下面验收清单进行真实设备验证。后台自动以微信 OPENID 派生用户标识，不接受客户端提供的身份或时间。

官方参考：
- https://docs.cloudbase.net/en/recipes/add-cloud-function-wechat-miniprogram
- https://docs.cloudbase.net/en/database/transaction
- https://github.com/wechat-miniprogram/minigame-demo/blob/master/CLOUD_README.md

## 已实现

- 四个页面分区：我们、一起、回忆、周榜。
- 邀请绑定；云端邀请一次性使用，自己不能加入自己，已有伴侣不能再绑定。
- 六类活动：散步、读书、自习、运动、电影、音乐。
- 双方加入后开始计时；双方各自完成确认后结算。
- 每类每天计分一次；情侣空间每天总上限 30 分。
- 重复完成请求不重复计分；云端事务串行化同一空间的修改。
- 上海时区的自然日、周一周榜；双方主动同意才公开匿名组合与分数，任意一方可以退出。
- 活动地点/计划与 300 字感想，仅空间成员可通过接口访问。
- 独立的定位质量判定函数及测试，仅作为后续接入基础，**未接入签到、不影响当前积分**。
- 加载、错误、重试、空状态和本地持久化。

## 第一版的明确范围

- 当前认证是双人确认；不能证明两个人真的同行或完成了活动，积分无现金或实物兑换用途。
- 没有照片上传、聊天、真实定位、连续轨迹，也没有连接电影或音乐平台。
- 时间线仅保留最近 300 条，积分账本独立保存。面向长期使用前应改为活动独立集合与分页；不要把此版当永久相册。
- 云模式在前台约每 15 秒刷新一次，离开页面停止定时刷新。也可以下拉刷新。
- 没有解绑、注销、导出或用户侧删除记录流程；正式收集长期个人数据前需要补齐。
- 尚未接内容安全审核、运营投诉入口和完整隐私声明；公开上线前需要结合实际类目补齐平台要求。
- 不支持多人、多段同时进行的活动。一个情侣空间一次只能有一个活动。
- 榜单只返回本周最高的 50 个组合；同分采用并列名次，边界处同分可能只显示部分组合。
- `爱在浙大` 是项目工作名，尚未核实名称可用性或取得学校官方授权；界面不使用校徽、不声称学校官方出品。

## 真机验收清单

- 两个不同微信账号绑定到同一空间，第三个账号不能读写该空间。
- 邀请过期、自邀、重复使用均被拒绝；错误邀请码连续提交受到限制。
- 两台手机同时确认，仅产生一条记录和一次积分。
- 修改客户端时间、发送伪造身份或积分均不影响服务端结算。
- 杀掉小程序重开能恢复状态，弱网下重复操作不会重复积分。
- 真机中文输入、键盘弹出、底部安全区、长感想显示正常。
- 不同情侣只看到自己的感想；榜单只含匿名组合与积分。
- 取消某一方的上榜同意后，重新查询榜单不再出现该组合。
